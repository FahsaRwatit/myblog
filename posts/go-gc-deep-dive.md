# Go GC 机制深度解析

## 前言

Go 的垃圾回收（GC）是很多面试必考题，但真正理解它需要从底层原理出发。

## 三色标记算法

GC 将所有对象分为三种颜色：

- **白色**：未被标记，可能是垃圾
- **灰色**：已被标记，但其引用的对象还未扫描
- **黑色**：已被标记，且所有引用的对象都已扫描

```go
// 触发 GC 的几种方式
runtime.GC()            // 手动触发
debug.SetGCPercent(100) // 默认值，内存翻倍时触发
```

## 写屏障（Write Barrier）

并发 GC 的核心难题是：GC 扫描的同时，程序还在修改对象引用关系。写屏障解决了这个问题。

Go 1.8 引入了**混合写屏障（Hybrid Write Barrier）**，结合了 Dijkstra 插入屏障和 Yuasa 删除屏障的优点。

## 生产调优建议

1. 合理设置 `GOGC` 环境变量
2. 使用 `sync.Pool` 复用临时对象
3. 避免频繁分配大量小对象
4. 用 `pprof` 定位内存分配热点

```bash
GOGC=200 ./myapp  # 允许更多内存，减少 GC 频率
```

> GC 调优的核心原则：**减少分配，延迟回收，复用内存**。
